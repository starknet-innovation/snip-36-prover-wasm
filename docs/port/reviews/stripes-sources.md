## Blocking findings

1. **The named block differential test does not execute block composition.** `crates/constraint-framework/src/prover/component_prover.rs:514` defines `MaskEval` with trace log size 16 and constraint bound 17. Its test calls ordinary dispatch, which requires bound at least `PARITY_MIN_LOG_SIZE = 20` at lines 158–163. Therefore `blocks_match_independent_cpu_with_positive_and_negative_masks` compares the existing full extension path. The similarly named disabled test also uses this small component. There is no targeted unit coverage of `evaluate_in_blocks`, its global row indices, or shifted-column classification. Existing end-to-end proofs are useful evidence but do not repair the mislabeled unit check. Preserve that fallback test; add a direct private-method test at the manageable log-17 domain and compare against CPU/full evaluation. Add a genuine block-eligible dispatch test or an independently testable dispatch predicate. Include shifted and unshifted columns, preprocessing, multiple blocks, boundary positive/negative offsets, and LogUp cumulative sums. This is an escalation under AGENTS' zero-coverage rule, and sign-off is withheld pending correction.

2. **New block FFT loops fail to compile without `parallel`.** `crates/stwo/src/prover/backend/simd/circle.rs:1018`, `:1025`, and `:1039` use Rayon methods unconditionally; the Rayon prelude is only imported under `cfg(feature = "parallel")`. The current WASM dependency graph explicitly enables parallel, so this does not demonstrate a mismatch in the tested candidate. It does regress the backend's supported serial configuration. Select `iter_mut()/iter()` under non-parallel and `par_iter_mut()/par_iter()` under parallel, then check both feature configurations. The split mutable/immutable halves are disjoint; each destination vector is assigned once.

3. **New unsafe FFT wrapper and expanded pool allocation lack explicit safety justification.** `crates/stwo/src/prover/backend/simd/circle.rs:965` introduces an unsafe raw-pointer FFT call, and `crates/stwo/src/prover/mempool.rs:98` expands the existing uninitialized allocation path. Upstream instructions require documented justification and escalation. The FFT contract must establish initialized source length `2^n` u32 elements; a writable destination of at least `subdomains * 2^n` elements; checked multiplication/shift arithmetic; `n >= 5`; 64-byte `PackedBaseField` alignment; offsets `index * 2^n * 4` preserving alignment; no source/destination aliasing; disjoint destination subranges; complete initialization by each FFT before safe reads; and valid twiddle layer lengths. For the pool, document the inherited write-before-read obligation, valid shifts, shortening semantics, and initialized growth. No native page-reclamation implementation was imported, and `from_fill` uses zero-initialized storage, which avoids a new source-callback initialization hazard. This review does not certify the pre-existing `Column::uninitialized` implementation itself.

## Invariants inspected

- Stripes concatenate in their original bit-reversed block order; Merkle grouping remains sorted stably by column size. Mixed-size lifting uses `(local >> (shift + 1) << 1) + (local & 1)`, matching the pinned full decommitment map and preserving the conjugate bit. Queried values retain input order and duplicates; authentication traversal deduplicates separately.
- Prefix interpolation uses the first domain split of the retained prefix's length. Source interpolation uses the canonical trace domain in bit-reversed order, then evaluates stripe zero on the committed extension domain. Source correctness remains a caller obligation: `new_with_sources` checks sizes but does not compare source values with the polynomial it already committed. A wrong source should cause verification failure, not acceptance.
- Nonzero mask offsets force full-domain storage; zero-offset block columns use local vector rows, whole columns use global vector rows. Denominator selection uses the global block row. The intended calculation looks consistent with the full path, but missing targeted block coverage prevents approval.
- Component groups preserve each component's original coefficient-power slice; reverse construction and accumulator splitting retain constraint order. Same-size components remain sequential, and groups own separate accumulation columns. Source objects require `Send + Sync`; source batches and polynomial transformations operate over disjoint owned destinations. Scratch pools use DashMap/Mutex ownership rather than sharing mutable column aliases.
- Samples retain original point order and repeated-doubling lifting. The Fiat–Shamir mix/draw sequence, FRI configuration, PoW and verifier remain unchanged. Regrown quotient batches retain global preassigned sample randomness; exact field addition permits merging batches. `add_accumulation` inserts new sizes in ascending order before lifted accumulation.
- Empty sourced evaluations are excluded from coefficient-to-stripe and destructive prefix interpolation. The current complete `prove_values` test covers the two previously observed source transition failures. Source columns are retained via explicit Arc ownership; no global value-transfer slot was added here.
